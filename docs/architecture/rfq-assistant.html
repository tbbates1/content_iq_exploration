Content IQ demo Architecture draft · 9 Nov 2026

IBM watsonx Orchestrate · Symplistic ContentIQ · Microsoft OneDrive

RFQ Assistant

A sales engineer asks about an old job in Orchestrate chat. The answer comes from that job's files only, and says which file and page it came from.

Think of a records room with one cabinet per project. The RFQ Assistant reads your request and works out which cabinet you mean. ContentIQ then opens only that cabinet and reads you the page.

How a question moves

Read it top to bottom. watsonx Orchestrate works out which project you mean. ContentIQ searches that project's files. OneDrive holds the files, and ContentIQ's built-in OneDrive Connect copies each project folder into its own agent.

What happens when you ask

The numbers match the blue arrows above. The example answer is real: it comes from the spec in synthetic_data/sample_documents/spec/.

  1. 1

    You ask in Orchestrate chat. “Use the GMD spec from the Quebrada Azul mill about 5 years ago. How many poles, and what rated speed?”

  2. 2

    The RFQ Assistant looks up the project. Its Find project tool searches the catalog for Quebrada Azul around 2021.

  3. 3

    It confirms which job, then gets its agent ID. Two Quebrada Azul jobs match, so it asks you to confirm the 2021 Expansion before going further.

  4. 4

    It asks that one ContentIQ agent. The Ask project tool sends the question with the 2021 Expansion agent ID and nothing else.

  5. 5

    ContentIQ searches only that project's index. It answers 72 poles at 10.13 rpm, from QAZ-EP-0000-265-SPC-00006-Q, page 15.

  6. 6

    You get the answer in the chat, labelled with the project. “QAZ Expansion (2021): 72 poles, 10.13 rpm. Source: GMD spec, page 15.”

  7. In the background, ContentIQ's built-in OneDrive Connect keeps each project's index in step with its folder. Live RFQs refresh nightly. Closed jobs are loaded once.

Who does what

You connect OneDrive to ContentIQ once, with its built-in OneDrive Connect. After that, each ContentIQ agent is pointed at one project folder.

Why not one agent for everything

ContentIQ has no folder filter when you ask a question. Its chat call takes an agent ID, a message and a thread ID, and the agent searches everything it holds. File names help a little, because each document number starts with the project code, but they don't keep other projects out.

Before building it

The design works on paper. These limits and open questions decide how far it scales.

Does someone have to link every project folder by hand?

Signing in to OneDrive happens once. After that, each project needs its own agent pointed at its own folder. In the UI that is one pick per project. A setup script could do it instead: list the folders with ciq_onedrive_list_files, start ciq_onedrive_ingest with the folder and the project's agent ID, and add the catalog row. It would run whenever a new project folder appears, and people keep saving files to OneDrive as they do today.

If that is still too many agents, use one agent per client instead. You get fewer agents, but projects for the same client share an index again.

Limits on our Starter plan

  • Only 1 scheduled ingest, so only one live RFQ refreshes on its own. Essentials Plus allows 3. Closed jobs don't need a schedule.
  • One ingest at a time per API key, so loading years of old RFQs runs one project after another. Our 7 test files took about 4 hours per full run.
  • 5 GB of storage. A real RFQ archive will be far larger.

Questions for Symplistic

  1. Can chat filter by folder or file metadata? If it can, one big agent with a filter is simpler than one agent per project.
  2. How many agents can one tenant have, and what does each cost?
  3. Can the API run a “changed and new” ingest without a schedule, so a nightly script could refresh many project agents?
  4. OneDrive Connect signs in as one account. Does everyone who asks then see answers from every file that account can open?
  5. Can the API ingest a whole OneDrive folder, and create the agent in the same call? That decides whether the setup script is possible.
