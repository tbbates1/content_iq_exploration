Project Searcher architecture

One ContentIQ agent holds all of Clients/. Our own sub-agent, Project Searcher, searches it several ways and keeps only the passages from the chosen project's files, using a folder map we build from OneDrive.

How a question runs

  1. A sales engineer asks a question in Orchestrate chat.
  2. RFQ Assistant splits it and sends each part, with the project, to Project Searcher.
  3. Project Searcher gets the project's file list from our folder map.
  4. It searches ContentIQ 2–4 different ways. Each search returns 15 passages and 1 table, each with its file name.
  5. It keeps only passages from the project's files and returns the facts.
  6. RFQ Assistant writes the answer and names the files.

Set up once

  • Link Clients/ to one ContentIQ agent with OneDrive Connect.
  • Let our backend read Clients/ through Microsoft Graph and keep the folder map in sync.
  • Give Project Searcher the folder map tool and the ContentIQ search tool.

Open risks (tested 9 Nov 2026)

  • Each search covers all 400 projects and returns only the top 15. The right project's passages may not make the cut.
  • source_hint doesn't filter. Ask Symplistic to make it fill the backend's source_filter.
  • Each search tool is tied to one ContentIQ agent. Attaching it to our own agent works (tested 2026-11-09).
